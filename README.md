# OKX Quant Hypotheses Lab — автономный бумажный журнал гипотез

Система **не торгует**. Она не выставляет ордеров, не хранит ключей биржи и не
управляет депозитом. Единственный результат её работы — журнал в Postgres:
что система предсказала, по какой цене, чем предсказание кончилось и какой
вывод из этого сделан.

Цикл фиксированный — **15 минут**:

```
котировки OKX  →  вселенная пар  →  15 категорий сигналов  →  связки-гипотезы
      ↑                                                               ↓
      └────  обучение весов по всей истории  ←  исход  ←  запись прогноза в БД
```

1. **Смотрим котировки.** Тикеры, свечи 15m, стакан, фандинг, открытый интерес
   — только публичные эндпоинты OKX, без аутентификации.
2. **Система сама выбирает вселенную** (~12 пар: ядро по ликвидности + разведка
   по мерит-скору), а не получает список от человека.
3. **Считаем 15 категорий сигналов** по каждому активу (импульс, объём, поток,
   стакан, деривативы, ликвидации, кросс-актив и т. д.).
4. **Строим связки** категорий и оцениваем их Early Value Score.
5. **Планировщик решает, сколько связок оформить гипотезами.** Решение
   принадлежит модели (`ai`), детерминированному правилу (`rule`) или запасному
   порядку при отказе модели (`fallback`) — и это решение сохраняется в БД.
   **Ноль гипотез — полноценный ответ**, а не ошибка.
6. **Прогноз фиксируется в БД**: направление, цена входа, цель, условие
   отмены, горизонт 15 минут, издержки в bps, контрольная сумма.
7. **Через 15 минут** система читает реальные котировки и записывает исход:
   `hit` / `miss` / `ambiguous` / `expired`, плюс MFE, MAE, чистый результат
   после издержек и тип ошибки.
8. **Веса категорий пересчитываются по всей накопленной истории** — и цикл
   повторяется бесконечно.

## Принципы честности журнала

Это не декорация, а свойства кода, закреплённые тестами в `tests/`:

| Принцип | Что это значит в коде |
| --- | --- |
| Нет данных — нет сигнала | Фолбэки OKX (синтетические свечи/стакан/фандинг/OI) помечаются `isLive: false` и **не попадают** в категории: уверенность 0, пропущенность 1 |
| Исход проверяется реальной ценой | Если цены на момент разрешения нет, прогноз получает `expired` + `data_gap`, а не «miss по цене входа» |
| Нет заглядывания в будущее | В MFE/MAE идут только бары, **целиком** лежащие внутри горизонта прогноза; незакрытый бар исключается |
| Обучение идемпотентно | Веса пересчитываются из всей истории одним SQL-агрегатом; повторный прогон не «накручивает» счётчики |
| Пустая база не выдумывает статистику | `hit rate` и Brier — `null`, пока нет решённых исходов (не «50 %» и не «0.2500») |
| Демо-истории больше нет | `POST /api/research/seed` возвращает `410 Gone`: журнал наполняется только реальными циклами |
| Расписание живёт на сервере | Цикл запускает `instrumentation.ts` при старте процесса, а не открытая вкладка браузера |

## Быстрый старт

Нужны Node.js 22+ и Docker (или свой Postgres 14+).

```bash
cp .env.example .env.local          # и вписать DATABASE_URL, если он отличается
docker compose up -d db             # Postgres 16 на 127.0.0.1:5432
npm install
npm run db:push                     # применить схему и индексы (drizzle-kit push)
npm run dev                         # http://localhost:3000
```

Автопилот стартует вместе с сервером и делает первый цикл сразу, дальше —
каждые 15 минут. Отключить: `AUTOPILOT=0` (циклы останутся доступны вручную —
кнопка Run или клавиша `R` в терминале).

Полностью в контейнерах:

```bash
docker compose --profile app up --build
docker compose run --rm app npx drizzle-kit push   # один раз, применить схему
```

### Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | **обязательна.** Postgres с журналом |
| `AUTOPILOT` | `0` — не запускать серверное расписание |
| `NVIDIA_API_KEY`, `NVIDIA_BASE_URL`, `NVIDIA_MODEL` | NVIDIA NIM (необязательно) |
| `OPENCODE_API_KEY`, `OPENCODE_BASE_URL`, `OPENCODE_MODEL` | OpenCode Zen (необязательно) |
| `GPT4FREE_BASE_URL`, `GPT4FREE_MODEL` | gpt4free, ключ не нужен (необязательно) |

Без ключей модель не вызывается: планировщик уходит на детерминированное
правило EVS, а разборы — на локальный glassbox-аналитик. Порядок провайдеров и
ключи, введённые в UI, хранятся в таблице `ai_provider_settings`.

Ключи биржи не нужны и не используются: ордеров нет.

## Проверка кода

```bash
npm run typecheck   # tsc --noEmit
npm run lint        # eslint (0 ошибок)
npm test            # vitest: 60 тестов чистых функций
npm run verify      # всё сразу
npm run build       # production-сборка (нужен доступ к Google Fonts)
```

Тесты покрывают чистую логику: контракт исхода, оценщик исходов (включая
защиту от look-ahead и от незакрытого бара), детектор режима (замёрзший рынок,
пила, сжатие, тренд), согласованность знака в категории деривативов, честность
признаков при отсутствии данных, байесовское сглаживание весов, разбор
параметров из ответа модели.

SQL-запросы (агрегаты обучения, LEFT JOIN журнала, статусные счётчики) в этом
прогоне не проверяются: эмуляторы Postgres молча искажают `COUNT(*) FILTER` и
не поддерживают `LATERAL`, поэтому такой тест дал бы ложную уверенность. Для
них нужна настоящая база — `docker compose up -d db`.

## Схема базы

Миграции — в `drizzle/` (генерация: `npm run db:generate`, применение:
`npm run db:push`, просмотр: `npm run db:studio`).

| Таблица | Что хранит |
| --- | --- |
| `assets` | Реестр отслеживаемых пар |
| `candles` | Сохранённое окно свечей 15m (топливо для бэктеста и walk-forward) |
| `signal_features` | Снапшот 15 категорий по каждому активу каждого цикла |
| `combinations` | Связки категорий и их Early Value Score |
| `hypotheses` | Оформленные гипотезы: формула, механизм, неопределённость |
| `forecasts` | **Бумажный журнал**: прогноз + исход + MFE/MAE + тип ошибки |
| `learning_weights` | Веса 15 категорий, hit-rate, Brier, выборка |
| `experiment_runs` | Журнал циклов: кто решал, что создано, метрики |
| `data_quality_logs` | Латентность, разрывы данных, отказ ИИ |
| `oi_snapshots` | Снимки открытого интереса |
| `ai_analyses` | Разборы модели и локального glassbox |
| `ai_provider_settings` | Порядок провайдеров, ключи, переопределения |
| `signal_filters` | Вето человека: пороги EVS, категорий, режимов |
| `selection_policy` | Кому принадлежит решение об отборе + потолок-страховка |

## API

Все эндпоинты — под `/api/research`, кроме `/api/health`.

| Метод и путь | Что делает |
| --- | --- |
| `POST /api/research/cycle` | Выполнить цикл сейчас (`{ "isManual": true }`) |
| `GET /api/research/cycle` | **read-only**: состояние планировщика и расписания |
| `GET /api/research/status` | Сводка для терминала (агрегаты считаются в SQL) |
| `GET /api/research/ledger` | Журнал прогнозов с LEFT JOIN на гипотезы |
| `GET /api/research/learning` | Веса, таксономия ошибок, калибровочные бины |
| `POST /api/research/learning` | Идемпотентный пересчёт весов по всей истории |
| `GET /api/research/edge`, `/walkforward`, `/heatmap`, `/combinations` | Исследовательские экраны |
| `GET/POST /api/research/filters`, `/policy`, `/ai-settings` | Настройки отбора и провайдеров |
| `POST /api/research/ai` | Спросить модель по контексту экрана |
| `POST /api/research/reset` | Очистить журнал. Требует `{ "confirm": true }` |
| `POST /api/research/seed` | `410 Gone` — демо-история удалена навсегда |
| `GET /api/health` | `select 1` к базе: 200 или 500 |

`GET` нигде не пишет в базу. Это принципиально: side-effectful GET выполнялся
префетчером браузера и сканерами, порождая циклы, которых никто не заказывал.

## Ограничения, о которых нужно помнить

- **Это не торговый робот и не сигнал-сервис.** Никакой статистики здесь не
  хватит на то, чтобы торговать на реальные деньги: журнал накапливает десятки
  исходов в день, а для выводов о преимуществе нужны тысячи.
- Выборка мала по построению: 15-минутный горизонт даёт ≤ 96 исходов на актив в
  сутки. Хитрейт на n < 30 — шум, и UI подписывает это прямо.
- Публичные эндпоинты OKX имеют лимиты; при отказе данные помечаются
  синтетическими и в признаки не попадают — цикл в этом случае честнее
  пропустить, чем придумать.
- Модель не принимает торговых решений: она выбирает, сколько гипотез оформить
  и с какими порогами, в пределах человеческого вето (`signal_filters`).

Не является инвестиционной рекомендацией.
