# Зонды аудита (воспроизведение приложения А)

Два скрипта, которыми получены числовые результаты аудита
[`research/code-audit-200.md`](../../research/code-audit-200.md). Они вызывают реальный код
движка (`feature-engine`, `combination-engine`, `outcome-evaluator`, `planner`) на синтетических
15-минутных сериях и печатают распределения. База данных и сеть не нужны.

## Запуск

```bash
npm install
npx tsx --tsconfig tsconfig.json scripts/audit/01-feature-engine-probe.ts
DATABASE_URL=postgresql://u:p@127.0.0.1:5432/x \
  npx tsx --tsconfig tsconfig.json scripts/audit/02-evaluator-and-planner-probe.ts
```

`DATABASE_URL` нужен второму скрипту только потому, что `planner.ts` импортирует `@/db`,
который бросает исключение при отсутствии переменной. Запросов к базе скрипт не делает —
подойдёт любой синтаксически валидный URL.

## Что проверяет каждый зонд

| Скрипт | Проверяемые находки аудита |
| --- | --- |
| `01-feature-engine-probe.ts` | 44, 45 (распределение режимов); 49, 50 (знак фандинга); 53–58 (корреляции категорий); 79, 81, 83, 87, 91 (свойства пула связок и EVS) |
| `02-evaluator-and-planner-probe.ts` | 51, 52 (дисперсия категорий); 79, 80 (lookback как no-op и размывание подписи); 99, 151 (достижимость бара исхода); 101, 102, 106 (утечки в окне разрешения и ветка RANGE) |

Зонды намеренно детерминированы (LCG-генератор вместо `Math.random`), чтобы цифры в аудите
можно было перепроверить байт в байт.

## Статус

Это диагностические скрипты, а не тесты: они печатают факты, но ничего не утверждают.
Фаза 4 плана работ (находки 189, 190) превращает их в полноценные unit-тесты с ожиданиями:
после исправления каждой находки соответствующий зонд должен давать новое, заранее записанное
значение (например, `RANGING > 0` для тихих серий, `mfe < 1%` без свечей до `fixedAt`).
