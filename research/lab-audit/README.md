# Аудит и исследование: как настроена лаборатория

Статус: **research only**. Код приложения в этом проходе не изменялся.

## Что это

Разбор проекта `ai-crypto-trading` и литературы по одному вопросу:

> Как должна быть **настроена** автономная лаборатория, которая сама находит стратегии, сама решает, когда и на каких данных их пересматривать, и делает так, чтобы результат после издержек был измерим?

Предмет прохода — конфигурация машины (ручки, лимиты, пороги, обучение, промпт, права), а не список стратегий. Рыночные идеи вынесены в отдельный файл и не являются главным результатом.

## Уровни источников

- **A** — прочитана содержательная часть (абстракт + ключевые числа/метод), цитата в реестре.
- **B** — прочитан абстракт или развёрнутая аннотация с конкретными числами.
- **C** — только обнаружение; в выводах не используется.

Распределение: **A — 180, B — 106, C — 23**. Восемь записей G00 — это код самого репозитория, а не внешняя литература.

Счётчик — нижняя граница покрытия, а не цель. **Оговорка о ссылках:** уровень A/B отражает глубину прочитанного содержания, а не повторную проверку доступности ссылки в этом проходе — часть доменов недоступна из песочницы. Идентификаторы, в которых не было уверенности, понижены до C и исключены из выводов. Если при следующем проходе ссылка не открывается, запись переводится в C, а утверждение, опиравшееся только на неё, — в `insufficient`.

## Границы

- Состояние проверено на **2026-10-19** (UTC), коммит `15f2df8`.
- Из песочницы нет доступа к `okx.com` и `arxiv.org`; веб-поиск доступен, поэтому часть источников уровня B.
- Бэктесты не запускались: нет `DATABASE_URL` и доступа к OKX. Все числа либо из источников, либо вычислены из формул кода (расчёты пропускной способности и мощности — в `configuration.md` §2).
- Отчёт не обещает доходность. Он фиксирует, какие значения ручек делают измерение осмысленным.

## Как продолжить

1. Открыть `state/state.json`, взять `next_action`.
2. Применить `config/lab.config.json` как реестр: каждую ручку либо внести, либо пометить технической.
3. Выполнить T0 (паспорт) и T1 (прибор) из `roadmap.md`; только затем запускать TE001–TE004.
4. Рыночные гипотезы из `hypotheses.jsonl` не проверять до T1: текущий прибор искажает исход.
